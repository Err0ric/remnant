| D262 | Quiet is normal holds the quiet alert (owner, 2026-11-14: "Expected quiet: marking holds the source's quiet alert up to a per-source ceiling (default 7 days), then it fires anyway (D236)"; amends D260, which left this open). The ceiling is the source's own **Quiet is normal for up to** days (1, 3, 7, 14, or 30; Claude Code sources start at 7). While a marked source's newest event (by its own date, `newest_event_at`, never later than when it arrived, read from the lake as Health reads it, never the time a watch was turned on; amended 2026-11-15 with the owner's approval, before which it counted from when a record was received) is inside those days, its quiet alert does not fire: no alert item, no message to alert targets, no `source.quiet` audit row, and the source reads Idle, not quiet. The source gap alert is the same silence signal (the quiet watch opens it when it fires), so it is held too; the hooks delivery check (a machine that keeps records undelivered) is not silence and is unchanged. When the days pass the alert fires exactly once, as it would have, with the real start of the silence and its whole length; taking the mark off has the next check (every 30 s) judge the alert by its own threshold. A source that never sent is never held, and a watch turned on for a source already silent most of its days fires when the real silence passes them. The hold is not stored: each check reads it from the lake with the rule Health uses (`inside_quiet_days`), so a restart neither loses nor repeats it. The newest event is read once per quiet episode, when a marked source's alert first becomes due, on the background query slot with a 10 s timeout, from that source's folders only, and kept until an event arrives (or an hour passes); a read that fails holds nothing (the alert is judged by its own threshold, D236) and never stops the other sources' checks. The alert's start and length are the newest event's when it is older than the watch's own clock; when records arrived more than an hour after that event's date it says "No new events for 7 d. Newest event dated 2026-10-08 12:00 UTC; last data arrived 2026-10-10 11:59 UTC." (owner, 2026-11-15), and otherwise "No events received for 7 d". The change is audited and answered without waiting on the lake. An alert already firing when a source is marked stays until events resume or a person closes it; the hold applies from the next quiet episode.
