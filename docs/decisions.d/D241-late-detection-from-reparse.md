| D241 | Late detection from reparse (owner, 2026-11-11, amends D233 and ADR-0050 row 7): matches from a rule re-run over reparsed events notify, as one grouped message per re-run through each rule's normal targets, never every target. A rule's normal targets are the alert targets of the schedules that run that rule and would have alerted on it in a scheduled run: enabled and not paused, the schedule's owner can read the reparsed source (CLAUDE.md rule 13), and the late matches meet the schedule's threshold (a percentage-change threshold cannot be judged for a late run, which covers another window, so late matches count as meeting it); a rule with matches and no such schedule, or a muted rule, gets its alert item and no message. When the re-run ends (done or partial), each target that should hear about at least one matched rule gets exactly one `late_detection` message ("Late detection from reparse") listing those rules with their match counts, with the source and the job's event time range (`time_min` to `time_max`), through the alert dispatcher like other alerts; a retry after a partial run sends one more only for the rules that matched in it; nothing is sent when nothing matched; each rule is announced once, in the transaction that queues the messages, so a restart never repeats one. The alert items a re-run raises or grows are marked late with that range (`alert_items.late`, `late_start`, `late_end`), and an item already open for the rule today that grows from a late run is marked late too; Alerts shows a "Late" badge with the range on the list and the alert's page | Accepted 2026-11-11 (owner) |
