| D251 | A file's read position survives a changed device number (owner, 2026-11-13; amends D250 and ADR-0051 row 2, found in the review of #579): a device number is not stable across restarts and remounts on Linux (LVM, NVMe, NFS, container bind mounts), so keying only by `(source, device, inode)` would read every text file again and store it twice. When no record has the open file's device number, a record of the same source and inode under another device number is used if both content hashes match, under any name (the file may have been rotated meanwhile), and is moved to the new number in the same transaction. The alternative, dropping the device from the key, lets two files on different file systems in one source share a record | Accepted |
