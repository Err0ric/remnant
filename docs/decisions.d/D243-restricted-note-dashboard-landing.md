| D243 | Restricted alerts note and the Dashboard as the start page (owner, 2026-11-12): (1) alerts in sources the viewer cannot read are never counted for that viewer. `GET /api/alerts`, `/api/alerts/count`, and `/api/alerts/lines` return `restricted` as a flag (true when an open alert read a source the viewer may not read; always false for an admin, who reads every source) in place of the count, and the Alerts summary strip and the Dashboard's Needs you banner show "Some alerts are in sources you can't read. Ask an admin for access." with no number. (2) `/` always opens the Dashboard for a signed-in viewer, never Health, with or without a panel (replaces the landing part of ADR-0031 and D83; unknown paths and `/overview` still open Health). When a source is not healthy or a gap is open, the Dashboard shows a one-line Health banner at the top in the Sources line's words, from the same `GET /api/overview` answer (no new query), with Open Health. While the banner shows, the Sources line at the bottom of the Dashboard is hidden, so the problem is said once; the banner always opens Health; when every source is healthy the bottom line shows as before (owner, 2026-11-12). The `restricted` flag on `?person=` comes from every open alert, never from the person-filtered ones, so it cannot tell whether a hidden alert names that person. | Accepted 2026-11-12 (owner) |
