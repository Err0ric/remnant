| D216 | Backend test suite speed (CI policy). The backend suite runs in one worker per vCPU (`pytest-xdist`, `-n auto`) in CI, the queue, and `make ci`. Tests over 8 s each carry the `slow` marker: a pull request's CI run in the private repo skips them (`-m "not scale and not slow"`), and the queue's local suite runs them with the rest (`-m "not scale"`) before it marks any PR ready, so no change reaches main without them; pushes, the public repo, and a manual run of the workflow run them too, and no scheduled run is added. The queue must never skip `slow`. In the tests, a YAML text that parsed once in a test process is handed back as a deep copy instead of parsing again (about a third of the suite's time was the same starter templates and library files re-parsed for each of about 700 apps built), and tests that only read the same built result share it per process, each with its own copy.
