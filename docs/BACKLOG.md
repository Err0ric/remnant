## 2027: company-wide local AI (owner, 2026-11-12; ranked high for 2027, nothing built)

The plan assumes all company AI use goes through one AI gateway with single sign-on, so one log feed names the person, the model, and the time for every request. Which gateway is the owner's choice and is not made yet.

1. **Parser template for the chosen gateway**: its request logs, or its OTLP output, into the OCSF columns AI usage already reads (person, service, model, tokens, time), with the usual fixture folder and a 10 KB garbage line.
2. **Inventory: an internal endpoint as an approved local AI service**: an admin marks an internal host and port as an approved local AI service, so AI usage counts it as Approved and Local and does not list it under possible AI.
3. **Decision on prompt content**: metadata only by default (who, model, size, time); storing prompt or answer text is a separate, explicit owner decision with its own classification and retention. Needs an ADR before any template stores content.
4. **Sigma rule for model-port access that bypasses the gateway**: firewall or flow logs showing a client reaching a model server's port directly instead of through the gateway.
5. **Laptop-local models**: a note in the guide on finding models that run on a laptop through software inventory, since they never reach the gateway.

When built, map the feature in SPEC section 7 to MITRE ATLAS AML.T0057 (LLM data leakage) and AML.T0040 (AI model inference API access), per security rule 12.
